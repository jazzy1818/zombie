Quarterly planning notes

This document is only a controlled practice surface. The toolbar deliberately contains two nested elements named Font size, and the style rows stay in the DOM while their menu is closed. With the checkbox below ticked, menu rows activate on mouseup and hide before the click event fires, exactly like Google Docs' Closure menus.

Run the practice lesson through the real extension 
// 1. Serve the repo root:  python3 -m http.server 8765   (run from the zombie/ folder)
// 2. Open http://127.0.0.1:8765/docs/resolver-fixture.html with the unpacked extension loaded.
// 3. DevTools → Console → switch the context dropdown from "top" to "Browser Teacher", then:
fetch('/docs/resolver-practice.json')
  .then(response => response.json())
  .then(lesson => __BT_DEV.runLesson(lesson));
// Click "Show me" in the panel and follow the steps.
Smoke-test __RESOLVE directly (same "Browser Teacher" console context) 
__RESOLVE.findSync({ scope: 'toolbar', name: 'Font size' })?.id
// Expected: "resolver-font-size" (the outer control, not its nested input).

__RESOLVE.findSync({ scope: 'toolbar', name: 'Bold' })?.id
// Expected: "resolver-bold" — the "(⌘B)" shortcut is stripped.

__RESOLVE.findSync({ scope: 'menu', name: "Apply 'Heading 1'" })
// Expected while the Styles menu is CLOSED: null.

__RESOLVE.waitForClick({ scope: 'toolbar', name: 'Styles' }).then(console.log)
// Click Font → { wrong: "Font" }.  Run again, click Styles → "correct" (menu opens).

__RESOLVE.findSync({ scope: 'menu', name: "Apply 'Heading 1'" })?.id
// Expected while the Styles menu is OPEN: "resolver-heading-one" (the "Heading 1►" row).

__RESOLVE.waitForClick({ scope: 'menu', name: "Apply 'Heading 1'" }).then(console.log)
// Click the Heading 1 row → "correct". With the Google Docs checkbox ticked the
// row hides on mouseup before click fires; __RESOLVE still answers "correct".

__RESOLVE.verify({ kind: 'label', selector: '#docs-toolbar-wrapper [aria-label="Styles"]', match: 'Heading 1' })
// Expected: true — this is the exact verify used by styles-toc step s4.

__RESOLVE.waitForClick({ scope: 'menu', name: 'Table of contents' }).then(console.log)
// Click Insert → { wrong: "Insert" }.  Run again, click Table of contents → "correct".
__RESOLVE.verify({ kind: 'dom', selector: '#resolver-toc-block' })   // → true
